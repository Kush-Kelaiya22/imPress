## Communication paths and their trust boundaries

| Path | Protection | Trust boundary and what is left |
|---|---|---|
| Browser → server | TLS (HTTPS required, HSTS); `HttpOnly` session cookie; CSRF header; `Origin` check on sockets | the server certificate (site CA or public CA, container guide) |
| Server → TrustedInstaller | same process, no network; no HTTP route reaches it | the server host |
| Gateway (C6) → server | per-device key (#66); TLS when the site enables it (`BACKEND_TLS`, `IMPRESS_DEVICE_HTTPS_ONLY`) | without device TLS the LAN can read device traffic: enable it ([#92](https://github.com/Kush-Kelaiya22/imPress/issues/92) tests it) |
| C6 ↔ S3 (SPI) | CRC16 per slot, framed records, bounded buffers | **physical**: the two boards sit in one enclosure; anyone who can attach wires can inject frames. No cryptography; [#182](https://github.com/Kush-Kelaiya22/imPress/issues/182) adds acknowledgement, not authentication |
| S3 ↔ student modules (ESP-NOW) | CRC16; de-duplication; enrollment format checks | **none on air**: unauthenticated broadcast ([#187](https://github.com/Kush-Kelaiya22/imPress/issues/187)); the server limits the damage (known students, active quiz, the gateway's own class, one answer per student) |
| Firmware download | approved, qualified, signed (site key) image; SHA-256 checked by the device before boot | the site signing key, kept outside the repository |

## Simulation and emulation: what is feasible

| Approach | ESP32 (module) | ESP32-S3 (hub) | ESP32-C6 (gateway) | Used in imPress |
|---|---|---|---|---|
| Espressif QEMU | yes | yes | **no target** | CI boots emulator builds of the hub and module (not the production flash modes) |
| Host-compiled firmware logic | yes | yes | yes | `firmware/*/test_host`, and the classroom simulator runs `firmware/protocol` via ctypes |
| Protocol-level simulation | yes | yes | yes | `firmware/sim/classroom_sim.py` (seeded faults), `backend/tests/gateway_sim.py`, the TrustedInstaller's OTA-client stage |
| Static binary inspection | yes | yes | yes | TrustedInstaller analysis of every upload |
| Running an arbitrary uploaded `.bin` | partial (QEMU, not production flash) | partial | no | not claimed; [#176](https://github.com/Kush-Kelaiya22/imPress/issues/176) evaluates an emulator for exact images |
| Hardware in the loop | | | | the hardware issues; the only evidence for radio, timing, power |

A passing simulation is never recorded as hardware verification ([test strategy](../testing/TEST_STRATEGY.md#simulation-levels)).

## Migration from v2.1

- **Database:** no schema change in 2.2 so far. Stored qualification reports from 2.1 are not attested; each is recomputed from its image the first time it is needed (no action).
- **Browsers:** everyone signs in once after the upgrade (the token moves from page storage to a cookie). Scripts that call the API keep sending `Authorization: Bearer`.
- **Gateways with their own key:** they now record only for their linked class. Make sure every gateway is linked (Admin → Modules) before the first lesson after the upgrade; an unlinked gateway's answers are skipped.
- **Secrets:** rotating `IMPRESS_JWT_SECRET` now also invalidates stored qualification reports (recomputed automatically) as well as sessions.
- **Firmware:** gateways may set `CLASSROOM_CODE` (empty by default). No change is required on existing boards.
