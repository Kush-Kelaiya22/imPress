## C. v2/v3 comparison

`v3` is one commit on top of `v2` that only changes firmware. Its CI failed in one job (a missing host-test stub). The full matrix is in [V2_V3_COMPARISON.md](V2_V3_COMPARISON.md).

- **Recovered from `v3` (#29):**
  - standard full-duplex SPI on both ends; the `v2` ends used incompatible wire modes, so slots never crossed;
  - FIFOs instead of a single overwritten pending slot;
  - always-on C6 SPI servicing;
  - a set-based student count;
  - the S3 heartbeat double-encoding fix;
  - DIO flash on the C6;
  - command relay logging.
- **Adapted:** the SPI clock became a Kconfig option (default 10 MHz). The C6 checks the CRC again, which `v3` dropped. The shared CRC function is used. The link task waits on a semaphore with a timeout instead of polling blindly. The C6 batch is bounded, because it grew without limit during Wi-Fi outages. The student set is cleared when the S3 reboots. The batch JSON dump is logged at DEBUG, not INFO.
- **Rejected:**
  - an in-place `memcpy` with identical source and destination (undefined behaviour);
  - a real-looking default enrollment number that was also the "unprovisioned" sentinel;
  - a committed `docs.zip`.
- **Deferred:** none. `v3` had no backend or UI changes to consider (#28).

## D. Implemented features

| Area | What changed | Why, and key decisions |
|---|---|---|
| CI (#26) | actions pinned to SHAs, IDF image by digest; hash-locked Python dependencies; `npm ci`; ruff; pip-audit and npm audit; coverage; a browser job; a clean-install job; one required **CI result** gate | reproducible, supply-chain-safe builds; one check to protect the branch |
| Database (#41) | versioned, transactional migrations with backups; foreign keys enforced; unique indexes behind every "already exists?" check; shared delete helpers | concurrent requests could create duplicates, and deletes left dangling rows. Alembic was rejected for a single SQLite file that must also adopt databases with no migration history |
| SPI link (#29) | see [C](#c-v2v3-comparison) | the `v2` link could not work |
| CSV imports (#31, #32) | questions; courses and sections. Preview or dry run first, strict validation, all-or-nothing commit, duplicates skipped, formula-safe export | bulk setup without silent data loss |
| OTA root causes (#33) | the version comes from the image itself (`version.txt` → `esp_app_desc_t`); success is reported only after the reboot and only for the expected version; HTTP status and size are checked; a push needs an uploaded image | updates "succeeded" without running, looped, or flashed error pages |
| Firmware registry (#35, #36) | uploads parsed as ESP-IDF images (chip, project, version, appended SHA-256, slot size); content-addressed and immutable; approval before deployment; deprecation; deletion only when unused | random bytes used to be accepted, and versions could be silently overwritten |
| Deployments (#38, #37) | a durable per-device state machine (waiting → … → health_check → success / rolled_back / failed / timed_out / unreachable / cancelled); canary and batches; concurrency, failure and attempt limits; timeouts; pause, resume and cancel; idempotency key; resumes after a backend restart; downgrades need confirmation | safe fleet updates. The state lives in the database, not in memory |
| Gateway OTA (#34) | a C6 client: check, download with streaming SHA-256, verify, install, reboot, health check (SPI, Wi-Fi, backend) or a 120 s watchdog, then rollback; app rollback enabled | the gateway could only be updated over serial |
| Diagnostics (#39) | the C6 heartbeat adds uptime, reset reason, boot count, lowest free heap and S3 link state; documented health rules (unknown, offline, updating, error, degraded, online) with reasons | "connected" hid reset loops and dead hubs |
| Inventory (#40) | one row per student module, keyed by its firmware device ID, with no history; filters; live through the presence push | joined modules were invisible (smoke step 7) |
| Hardware (#30) | PSRAM optional on the S3; measured footprints; minimum and reduced-flash configurations | the hub image refused to boot without PSRAM it never used |
| Packaging (#42) | `install.sh`, `start.sh`, `init_env.py` (generated secrets, never the defaults), `smoke_test.py`; `VERSION` reported by `/health` | one tested install path |
| Tests (#43) | simulated gateway; e2e quiz and OTA flows; fault injection | whole-flow confidence without boards |
| Docs (#44), security | README to the brief's structure, with badges from real data only; versioning, recovery, hardware, testing and security docs | |

**Defects found and fixed along the way:**
- the teacher's class delete returned 500;
- hard deletes left dangling references;
- registration dropped the reported firmware version;
- the CSV class import crashed on an invalid capacity;
- the C6 relayed every OTA prompt to the S3;
- `rolled_back` recorded the failed version as the running one;
- a relayed student heartbeat overwrote the gateway's battery and RSSI;
- the class page's live devices panel never started (since the first commit);
- *OTA pending* counted only one engine state;
- a database error on commit was an unhandled 500.

## G. Remaining risks

| Risk | Impact | Tracking |
|---|---|---|
| **No hardware verification of any v2.1 feature** | the SPI link, OTA, rollback, diagnostics and the inventory may behave differently on boards | [HARDWARE_VALIDATION.md](../testing/HARDWARE_VALIDATION.md) |
| Firmware images unsigned; device traffic plain HTTP; one shared device key | a party on the network or holding the key could serve firmware | #66 |
| Personal data in git history from before `v2` | exposure if the repository is public | [go-live checklist](../guides/deployment.md#4-go-live-checklist); purging needs a force-push, which is the owners' decision |
| Student modules have no OTA path | they are updated by hand over serial | [known issues](../reference/known-issues.md) |
| The S3's own reset reason and heap are not reported | hub problems are diagnosed only over serial | [system audit](SYSTEM_AUDIT.md) A14 |
| Reduced-flash hub profile is built, not booted; the backend's slot check assumes 4 MB | an oversized image could pass upload and fail on the device | [requirements](../hardware/CLASSROOM_NODE_REQUIREMENTS.md#reduced-flash-hub-profile-built-not-booted) |
| One uvicorn worker by design | throughput is bounded by one process | [backend scaling](../architecture/backend.md#scaling-and-limits) |
| No license file | reuse terms undefined | [README](../../README.md#license) |
| One intermittent browser-test timeout, seen once locally | possible flake | will be investigated if it recurs |
