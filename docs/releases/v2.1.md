## Requirements

- **Server:** Linux x86_64 with Python 3.12 or later, or a host with Docker. It must be on the same network as the classrooms.
- **Each classroom:** one gateway (ESP32-C6, 8 MB flash) and one hub (ESP32-S3, 32 MB octal flash), connected as shown in the [wiring diagram](https://github.com/Kush-Kelaiya22/imPress/blob/{{tag}}/docs/reference/hardware.md#s3--c6-wiring).
- **Each student:** one module (ESP32, 4 MB flash, four buttons).
- **To flash:** ESP-IDF v6.1 to build with your settings, or `esptool` 5 for the prebuilt images.

## Install and set up

### 1. Start the server

Use the install script or the container.

**Install script**

```bash
unzip {{asset}}.zip && cd {{asset}}
scripts/install.sh
IMPRESS_HOST=0.0.0.0 scripts/start.sh
```

**Container**

```bash
docker run -d --name impress --restart unless-stopped \
  -p 8000:8000 -v impress-data:/data \
  ghcr.io/kush-kelaiya22/impress-backend:{{owner}}-{{version}}
docker logs impress
```

On the first start, the log shows the `admin` password and the device API key. Record both. The log shows them one time only.

### 2. Log in

Open `http://<server-address>:8000` and log in as `admin`. Change the password immediately.

### 3. Prepare the devices

1. Set the Wi-Fi name and password, the server address and the device API key, then build and flash. Do this for the gateway (`firmware/class_c6`, menu **imPress C6 Gateway Configuration**) and the hub (`firmware/class_s3`):
   ```bash
   idf.py menuconfig
   idf.py -p <port> erase-flash flash monitor
   ```
2. Flash each student module from `firmware/student`. On the first start, enter the student's 10-character enrollment number with the buttons.

Flash each gateway and hub over USB one time with this release. After that, update them over the air. To flash the prebuilt images without a build, see [flash prebuilt images](https://github.com/Kush-Kelaiya22/imPress/blob/{{tag}}/docs/guides/releases.md#flash-prebuilt-images).

Production settings (HTTPS, a service unit, backups): [deployment guide](https://github.com/Kush-Kelaiya22/imPress/blob/{{tag}}/docs/guides/deployment.md).

## First use

1. **Admin:** on the **Courses** and **Classrooms** pages, create a course and a class. Set the class's room label (`classroom_code`) to the room of its gateway.
2. **Admin:** on the **Students** page, add the students or import a CSV file, and enroll them in the class.
3. **Teacher:** open **My Classes**, then the class, and click **Activate** at the start of the lesson. The gateway connects to the active class of its room.
4. **Teacher:** click **+ New Quiz**, add the questions, then click **Start**. Each student presses A to D. The live count goes up.
5. **Teacher:** click **Results** to see the answers for each question. Click **Deactivate** at the end of the lesson.

Step-by-step guides: [Teacher Guide](https://github.com/Kush-Kelaiya22/imPress/wiki/Teacher-Guide), [Administrator Guide](https://github.com/Kush-Kelaiya22/imPress/wiki/Administrator-Guide).

## Check the installation

```bash
curl http://<server-address>:8000/health
python3 scripts/smoke_test.py --base http://<server-address>:8000 --password <admin-password>
```

- `/health` must show `"status":"healthy"` and `"version":"{{version}}"`.
- The smoke test must end with `smoke test passed`. For the container, add `--device-key <device API key>`.
- In the web app, **Modules** must show the gateway as `ONLINE`.

## Setup problems

| Problem | Do this |
|---|---|
| The server does not start: *Refusing to start with default secrets* | Run `scripts/install.sh` again. It writes new secrets to `backend/.env`. |
| Other computers cannot open the web app | Start with `IMPRESS_HOST=0.0.0.0`, and open port 8000 in the firewall. |
| The gateway is not `ONLINE` | Check its Wi-Fi settings and server address. Run `curl http://<server>:8000/health` from the same network. |
| The server log shows 401 or 403 for devices | Make sure the gateway's device API key is the server's `IMPRESS_DEVICE_API_KEY`. |
| A student module shows `No mesh found` | Switch on the hub first. Make sure that both use the same Wi-Fi channel. |
| Answers do not count | Make sure that the student is registered and the class is active. |

More problems and their causes: [troubleshooting: setup problems](https://github.com/Kush-Kelaiya22/imPress/blob/{{tag}}/docs/guides/troubleshooting.md#setup-problems).

## Upgrade

1. Back up the database (`backend/impress.db`) or the `impress-data` volume.
2. Install this release the same way as the earlier one. Keep `backend/impress.db`, `backend/.env` and `backend/firmware_bins/`, or start the new container with the same volume.
3. Start the server. It updates the database automatically and makes a backup first.
4. To update the boards, upload the images on the **Firmware** page and click **Deploy**.

From 2.0, and how to roll back: [upgrading](https://github.com/Kush-Kelaiya22/imPress/blob/{{tag}}/docs/guides/deployment.md#5-upgrading), [recovery procedure](https://github.com/Kush-Kelaiya22/imPress/blob/{{tag}}/docs/firmware/RECOVERY_PROCEDURE.md).
